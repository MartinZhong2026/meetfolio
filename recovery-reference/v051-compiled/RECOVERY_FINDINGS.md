# Meetfolio 0.5.1 → 0.6.0 恢复审计｜2026-10-26

## 一句话结论

**用户判断大体正确：此次实际上传的 0.5.1 Windows 安装包，已经具备 0.6.0 Desktop Lite 的绝大多数主要功能。0.6.0 的显著变化确实是英文界面与英文发布说明。** 但仅改界面语言不能自动恢复官方 0.6.0 的原始源码、完整打包版本、Windows/Mac Release、最后修复项或 Git 历史。

不能把 0.5.1 安装包改个版本号、替换部分文字后就声称它与先前官方 v0.6.0 逐字节或行为完全一致。

## 已从用户上传的原件确认

原件：`Meetfolio-0.5.1-Windows-x64-Installer.zip`

- ZIP 里有 Windows NSIS 安装程序、`README-INSTALL.md`、SHA256 清单，无可编辑的 TypeScript 项目代码。
- ZIP CRC 检查通过；安装程序的 SHA-256 与原始清单吻合：`0164090a6a34974d2148fb9d01ca2621c3ac1ba7438e211cdc74623a9992f398`。
- NSIS 内有 **1569 条安装文件记录**，解包总量约 407 MB，可被系统 libarchive 解码。
- `resources/app.asar` 可提取，其 `package.json` 明确写 `@meetfolio/desktop` **v0.5.1**。
- 成功校验并提取 Electron 的编译后主进程 `dist/main.cjs`、预加载 `dist/preload.cjs`、完整 Vite 生产 UI（JavaScript/CSS）、独立 X-ASR 的 JS 运行时与原生依赖清单。
- 原生主进程实际从 `process.resourcesPath/ui` 载入生产 UI，所以纯前端文案替换理论上可以复用已有 native bridge，而无需重写录音引擎。

## 本轮英文界面预览补丁

翻译来源是 **v0.5.1 安装包内真正执行的生产前端 JS**，而不是之前 v0.1 恢复包里较旧的 React 源码。

- 使用 TypeScript 的 JS AST 解析定位 **399 个含中文文本节点**，逐项翻译，并只改这些字符串/模板文案。
- 原始与新版本的总 AST 节点数同为 **80,353**，函数调用表达式同为 **3,392**，属性访问表达式同为 **5,490**，字符串/模板节点同为 **3,054**。
- 新 JS 的语法解析和 `node --check` 通过；中文 UI 文案节点从 399 降到 **0**。
- 重新生成前端资源文件名、`index.html` 英文语言声明、离线 shell Service Worker cache 标识。
- **保持 `app.asar`、ASR 引擎、录音/回放/PDF 原生代码不变**；仍要借助用户自己安装的原 v0.5.1 Windows 程序运行。

包名：`Meetfolio_v051_English_Overlay_Preview.zip`，内含补丁文件、操作说明、PowerShell 安装/回滚脚本及 manifest。

### 为什么不叫官方 v0.6.0？

1. 未拿到当时已发布的 v0.6.0 源码或安装包，无法逐文件比对；已知 0.6 还包含发布打包和英文产品描述等修改。
2. English Overlay 是**编译后 UI 资源级别的修补**，不是重新编译原 TypeScript 源码，也不包含完整 Windows 安装器、Mac DMG。
3. 当前 Linux 环境无法执行原 Windows Electron 安装程序、测试真实 Windows 麦克风或完成端到端实体录音验收。
4. 修改后的版本号仍是 **v0.5.1**；擅自伪装发布版本不符合可靠的软件版本管理。

### 测试/回滚注意

先导出 JSON **以及单独的 WAV**，在真实访谈以外的虚构数据上测试。若用户手动安装英文补丁，先完整复制原有 `resources/ui`，关闭 Meetfolio 后覆盖三类前端资源；异常时恢复备份即可。勿改变操作系统全局安全保护。

## 对恢复完整项目源码的意义

- 旧 v0.1 源码 ZIP 仍是可编辑的 Electron/React/TypeScript 起点，但**明显落后于此 0.5.1 安装包的已实现功能**。此前 Stage 1 上许多“待重建”项目现在可从 v0.5.1 的 `app.asar` 和运行时 JS 确认确实存在。
- 这次提取到的是**已编译的 JS 和前端 Bundle**，不是 GitHub 原始 TypeScript 项目，也没有 Git 提交史。能做阅读、逻辑参考、资源补丁，不等于能直接拿来无损重建所有原始开发源码。
- 要真正恢复可继续迭代的 v0.6.0 项目，理想路线仍是：寻找 Codex Cloud 原工作区/Git bundle；找不到时，用 v0.1 编辑源码 + 0.5.1 编译后代码逐模块复原原生 WAV、模型和资料逻辑；再新建持续集成和跨平台构建、真机回归验证。
- 独立网页版 PR #15 是另一条新分支，不能混在桌面 0.6 里假称已恢复。

**交付性质：本轮提供了一个有回滚机制的英文 UI 预览补丁，以及完整可追溯的 0.5.1 关键编译资源审计。并未宣称恢复官方 v0.6.0。**
